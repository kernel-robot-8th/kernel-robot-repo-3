# Pinky fleet 운영

## PC 관제

관제는 사용자 서비스 `pinky-fleet.service`로 실행합니다. 로그인 시 자동 시작되며 실패 시 재시작합니다. SSH 비밀번호는 서비스 파일에 저장하지 않습니다. 서비스 재시작 후 웹에서 비밀번호를 다시 입력합니다.

```bash
systemctl --user status pinky-fleet.service
systemctl --user restart pinky-fleet.service
systemctl --user stop pinky-fleet.service
journalctl --user -u pinky-fleet.service -f
```

수동 실행은 `./run.sh`입니다. 이미 관제가 있으면 주소를 출력하고 종료합니다. 기본 경로는 로봇별 ROS 도메인 직접 구독입니다. 도메인 0의 RViz 등에서 브릿지가 필요하면 서비스를 정지한 뒤 `./run.sh --bridges`로 실행합니다. 다른 프로젝트의 브릿지는 정리하지 않습니다.

사용자 서비스 재설치: `/usr/bin/python3 scripts/install_user_service.py`. 등록과 시작을 같이 하려면 `--start`를 사용합니다.

## 로봇 코드 적용

연결 후 각 기체의 **주행준비**로 `fleet_control_v4`를 적용합니다. 이전 감시기 또는 서로 다른 공유 구역 설정으로는 새 주행을 시작할 수 없습니다. 설치 파일은 압축 번들 해시를 검증한 뒤 적용하며, 실제 소스 해시는 로봇의 `~/.cache/pinky-fleet/nav2/source_manifest.json`에 기록합니다.

`map-proto.yaml`을 선택해 주행준비하면 별도 `config/keepout/keepout_mask.pgm` 마스크가 Nav2 전역·지역 costmap에 적용됩니다. 다른 지도에서는 필터를 켜지 않습니다. 마스크 범위를 바꾸면 `python3 scripts/create_keepout_mask.py`로 다시 만들고, 로봇 Nav2를 다음에 준비할 때 새 파일이 전송됩니다. 실행 중인 로봇에는 즉시 재시작을 걸지 않습니다.

정상 모터 명령 경로:

`Nav2 /cmd_vel_nav2 → 행동 선택 /cmd_vel_selected → 독립 final_guard → /cmd_vel`

최종 감시기는 20Hz로 검사합니다. 명령 0.3초, LiDAR·초음파·TF 약 0.6초, 경로 컨텍스트 1.5초, 관제 허가 1.5초 한도를 넘으면 정지합니다. 작업자 정지는 이보다 우선합니다. 모든 센서·주행 코드가 같은 프로세스에 묶이지 않습니다. 최종 감시기 자체 강제 종료·PC 전원 차단·바퀴 미끄러짐까지 물리적으로 보증하는 기능은 아니며, 기체 모터 제어기의 명령 타임아웃은 실제 장비에서 별도로 확인해야 합니다.

## 차체 및 초음파 장착 위치

`config/robot_geometry.json`에서 공통값과 `robots.10/11/12`별 재정의를 설정합니다.

- `half_length_m`, `half_width_m`: 바퀴를 포함한 중심 기준 반치수. 기본 각 0.07m.
- `padding_m`: 차체 추가 여유.
- `ultrasound_x_m`, `ultrasound_y_m`, `ultrasound_yaw_rad`: base_footprint 기준 센서 장착 위치·방향.
- `ultrasound_fov_rad`: 센서 시야각. 기본 0.35rad는 실측값이 아닙니다.
- `sensor_pose_measured`: 장착 좌표를 직접 확인한 경우 true. false이면 Range 프레임의 TF가 있을 때 자동 적용하며, 없으면 기본값을 사용하고 화면에 미실측으로 표시합니다.
- `detour_offset_m`: 최소 측면 우회 폭. 기본 0.10m. 차체 반폭 + 3cm보다 작게 적용하지 않습니다.

실측하지 않은 장착 좌표를 실측값으로 표시하지 않습니다. IR 보정값은 이 설정과 별도로 기체마다 유지합니다. 센서에 timestamp가 있으면 소스 지연도 검사하고, stamp가 0인 드라이버는 수신 시각으로 검사합니다.

## 회피 및 차선 복귀

정지 → 전체 후보 궤적의 차체 여유를 비교해 좌우 선택 → 약 60도 회전 → 측면 10cm 이상 확보 → 진행 방향 복원 → 장애물 전방 통과 → 차선 방향 회전·접근 → 진행 방향 정렬 → 새 IR 샘플 3개 이상과 CH2 흰색 0.3초 연속 확인 → 일반 주행입니다. IR 보조를 끈 임무는 기하학적 복귀 후 Nav2에 인계합니다. 불확실한 상태로 성공 처리하지 않으며 60초/출발점 반경 70cm 한도를 둡니다.

초음파 감지점은 센서 장착 위치와 시야각을 반영해 기억합니다. 단일 센서로 실제 물체 전체 폭을 측정할 수는 없습니다. 공간이 없거나 패턴을 찾지 못하면 정지합니다. 회피 중에는 Nav2 목표를 일시 취소하고 경로 heartbeat를 유지하며, 복귀 확인 후 같은 목표를 재개합니다.

## 공유 구역

7번 교차로, 5번 도킹, 주차장 출입을 예약합니다. 교차로와 도킹은 중심 약 40cm 이내에서 먼저 허가를 요구하며, 주차장 출입은 이송 구간 전체를 한 대씩 허용합니다. 좌표는 관제 시작 시 P0의 7번·5번 웨이포인트와 주차장 설정에서 가져옵니다. 좌표를 바꾸면 관제를 재시작하고 로봇 주행준비로 같은 설정을 적용합니다.

허가는 로봇별 도메인의 `/fleet/lease`로 0.25초마다 전송합니다. 같은 예약에는 한 대만 허가하고, 중복·역순 heartbeat는 수명을 갱신하지 않습니다. 웹 브라우저를 닫아도 관제 서비스가 살아 있으면 임무가 계속됩니다. 관제 서비스가 멈추거나 허가가 갱신되지 않으면 1.5초 후 정지합니다. 관제를 재시작했을 때 추적되지 않는 과거 임무는 자동 재개하지 않습니다.

예약은 `data/traffic_reservations.json`에 유지합니다. 통신이 끊긴 점유는 자동 해제하지 않습니다. 최신 위치로 출구 밖을 확인하거나 주차장 복귀 완료를 확인한 후 해제합니다. 수동 예약 해제도 최신 위치와 정지 조건을 검사합니다. 저장 실패·손상 시 허가를 중단합니다. 이는 지정 구역의 순서 제어이며, 전 구간 다중 로봇 경로 계획을 대체하지 않습니다.

## 상태와 로그

화면은 마지막 준비 성공 기록과 현재 주행 가능 상태를 구분합니다. 준비 성공 기록만으로 출발 버튼이 활성화되지 않습니다.

- PC ROS 수신 기록: `logs/telemetry.jsonl`과 회전 파일.
- 서비스 실행·오류: `journalctl --user -u pinky-fleet.service`.
- 로봇 원시 IR·정규화·행동 선택 명령: `~/.cache/pinky-fleet/logs/behavior.jsonl`.
- 로봇 최종 모터 명령·오도메트리·정지 이유: `~/.cache/pinky-fleet/logs/final-guard.jsonl`.

JSONL은 각 파일 5MB, 이전 파일 4개까지 보관하며 디스크 기록은 별도 큐에서 처리합니다. 반복 기록은 5Hz로 제한하고 상태 변화는 즉시 기록합니다. 기체 시계가 다를 수 있으므로 PC 수신 기록을 공통 시간축으로 사용합니다. 비밀번호·HTTP 요청 본문은 기록하지 않습니다.

## 검증 범위

오프라인 회귀 테스트는 ROS 모터 발행이나 SSH 없이 실행합니다.

```bash
/usr/bin/python3 -m unittest discover -s tests -p 'test_*.py' -v
```

실측 장착 위치·바퀴 폭, 실제 센서 시야, 동시 진입·도킹 대기·관제 허가 단절·회피 후 IR 복귀는 로봇 재연결 후 확인해야 합니다. 오프라인 통과를 물리 주행 성공으로 간주하지 않습니다.
