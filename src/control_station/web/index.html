재고를 불러오는 중…

주문 가능은 선반에 있는 개수에서 시작 전·진행 중 주문이 잡아 둔 개수를 뺀 값입니다. 카메라 값은 같은 개수가 세 번 이어서 읽혀야 바뀌고, 팔이 일하는 동안에는 마지막 확인값을 씁니다. 재고를 모르는 물건은 0개로 치지 않고 주문을 닫습니다. 직접 수량은 카메라 대신 작업자가 센 개수로 팔고, 카메라 기준으로를 누르면 다시 카메라 값을 씁니다.

실시간 추적 확인 중

천장 카메라로 Pinky 윗면 마커를 재서 등록된 주차 위치와 비교한 관측값입니다. 실시간 상태는 화면 표시용이며, 팔 단계 진행은 Pinky 도착 신호 이후 프레임으로 내리는 확정 판정으로만 정합니다. 보정 안내는 운영자 참고용이고, 이 화면은 로봇 명령을 보내지 않습니다.

팔 수동 조작

주문 흐름 밖에서 팔을 한 번씩 움직여요. 누르기 전에 팔 주변과 핑키 위를 비워 주세요.

물건을 고르면 그 물건만 집도록 학습한 정책이 팔을 움직여 핑키 위에 올려요.

정책 목록 확인 중

누르기 전에

  1. 팔이 쉬는 자세이고, 팔 주변에 사람 손이 없어요
  2. 핑키가 적재 자리에 서 있고 쟁반이 비어 있어요
  3. 집을 물건이 그 팔 앞 선반에 있어요

지금 명령

보낸 명령이 없어요

복구

정책이 중간에 멈췄거나 팔이 어색한 자세일 때 기록해 둔 home 자세로 돌려보내요.

명령 기록
명령상태대상·칸워커·마지막 이벤트
명령을 불러오는 중…
어떻게 동작하나요
  • 명령은 관제 서버의 대기열에 들어가고, 그 팔의 워커(scripts/omx_lerobot_worker.py)가 가져가서 수락해야 팔이 움직여요. 워커가 없으면 명령은 기다리다 만료돼요.
  • 정책으로 집기는 먼저 정면 캠에서 그 물건이 한 칸에 보이는지 확인해요. 못 찾으면 이유를 보여 주고, 확인 없이 실행할지 한 번 더 물어요. 정책은 위치를 입력으로 받지 않고 자기 카메라로 물건을 찾으므로, 칸은 물건이 있었다는 근거로만 남아요.
  • 정책이 쉬는 자세로 돌아오면 멈추고 home 자세로 맞춰요. 실제로 집어서 놓았는지는 확인하지 않으므로 결과는 결과 불명으로 남고, 현장을 보고 현장 확인 완료로 닫아요.
  • 화면의 정지는 하드웨어 비상 정지를 대신하지 않아요.

학습 정책 한 번 실행 상태 확인 중

정책 실행 상태를 불러오는 중…

설정한 총 액션 수에서 멈춰요. 액션 상한 도달은 집기·배치 성공을 뜻하지 않으니 영상과 실제 팔을 확인하세요.

칸으로 이동 개발용 · ?dev=1

좌표·칸 방식(2026-11-11에 정책 흐름으로 바꾸며 접음)에서 쓰던 명령이에요. 칸 앞 자세로만 움직이고 집기로 이어지지 않아요.

작업 이력

불러오는 중
이전 형식 작업 (대상 하나, 색상·선반 층 조건)

대상 필드는 선택 입력입니다. 하나라도 입력하면 대상 종류가 필요합니다. 색상·선반 층은 기록만 하며, 팔 단계는 대상 종류로 학습 정책을 고릅니다.

작업을 불러오는 중…

작업을 선택하면 단계와 생성 이력을 볼 수 있습니다.

작업 등록은 기본 정보와 선택한 대상 조건을 이력에 저장할 뿐, 인식이나 로봇 명령을 실행하지 않습니다.
