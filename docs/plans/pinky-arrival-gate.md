# Pinky 도착 판정과 로봇 진행 계획

천장 카메라의 Pinky 주차 판정을 관제 작업 흐름에 넣는 계획입니다. 판정 방식은 [실행 방법](../implementation/runbook.md#천장-카메라-pinky-주차-판정), 결과 형식은 [데이터·인터페이스 계약 초안](../spec/interface-contracts.md)의 "Pinky 주차 정렬 관측", 팔 단계 시작 조건은 [시스템 명세](../spec/system-spec.md) 4.4절에 있습니다.

## 결정 (2026-11-02)

- 주차 판정은 **도착 완료 판정**입니다. 화면에 보여 주기만 하는 값이 아니라, 판정 결과에 따라 다음 로봇 명령(팔 단계 시작)을 보낼지가 정해지는 **작업 진행 조건**입니다.
- 판정 자체는 명령을 보내지 않습니다. 판정은 관측 결과를 내고, 관제 오케스트레이터가 그 결과를 보고 다음 명령을 보냅니다. "관측 결과와 명령 결과를 섞지 않는다"는 기존 규칙은 그대로 지킵니다.
- 천장 카메라는 관제의 Head Camera와 같은 실물 카메라(HCAM0)입니다. 관제가 Head Camera feed로 판정하며, 관제가 카메라를 여는 동안 CLI는 같은 카메라를 열 수 없습니다.

## 흐름

```
Pinky 이동 (Nav2) 최종 성공 결과
  → 관제: 주차 판정 요청 (이동 성공 이후에 찍힌 프레임만 사용)
      ├─ ARRIVED      → 팔 단계 시작 (OMX 명령)
      ├─ MISALIGNED   → 팔 단계를 시작하지 않음 → Pinky 보정 (아래 미정 항목)
      └─ 판정 불가     → 팔 단계를 시작하지 않음 → 재판정 또는 운영자 확인
         (NOT_FOUND / AMBIGUOUS / VIEW_UNVERIFIED)
```

Nav2 이동 성공만으로는 팔 단계를 시작하지 않습니다. 이동 성공과 `ARRIVED`가 모두 있어야 합니다.

## 미정 항목

| 항목 | 현재 초안 | 정할 사람 |
|---|---|---|
| `MISALIGNED`일 때 Pinky 보정 | 자동 재주행 없이 어긋난 양(앞·왼쪽 mm, yaw)을 운영자에게 표시 | Pinky 담당 |
| 자동 보정을 한다면 방식 | Nav2 목표 재전송 또는 `cmd_vel` 미세 이동 중 선택. 최대 횟수와 1회 보정 한계를 정하고, 넘으면 `NEEDS_INTERVENTION` | Pinky 담당, 관제 담당 |
| 판정 불가일 때 | 재판정 횟수·간격, 운영자 확인으로 넘기는 시점 | 관제 담당 |

## 실물 로봇 조건으로 쓰기 전에 필요한 것

| 항목 | 현재 (2026-11-02) | 필요한 것 |
|---|---|---|
| 허용 오차 | 임시 50 mm / 10° | 팔이 감당할 수 있는 어긋남과 Nav2 재주차 반복성을 재서 결정 |
| 재주차 반복성 | 손으로 다시 세운 3회만 측정 | Pinky 주행(Nav2)이 완료되면 Nav2로 주차해 다시 측정 |
| 시야 확인 | 팔 나무판 위 1번 고정 마커 | 유지. 끄면 카메라 영상 밀림이 가짜 `MISALIGNED`로 나옴 |
| 카메라 경로 | Head Camera 기본 by-id가 포트 10의 다른 HCAM0을 가리킴 | `CONTROL_STATION_HEAD_CAMERA`를 포트 기준 by-path로 지정 |
| 등록 파일 상태 | `DRAFT_ONLY`, `usable_for_robot_control: false` | 판정 결과를 진행 조건으로 써도 되는지 승인하는 절차 |

## 구현 단계

1. 관제 판정 API `GET /api/parking-spots/{spot_id}/check` (구현됨)
2. 판정 결과를 작업 이력에 `PARKING_OBSERVED` event로 기록
3. 관제 화면에 판정 상태와 어긋난 양 표시
4. 오케스트레이터에서 팔 단계 시작 조건으로 연결 (이동 성공 + `ARRIVED`)
5. `MISALIGNED` 보정 흐름 (미정 항목 결정 후)
